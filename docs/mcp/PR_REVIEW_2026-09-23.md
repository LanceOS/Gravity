# MCP follow-up PR review — 2026-09-23

This review covers the **uncommitted working tree** on `codex/mcp-reliability-and-granularity`, including new files and regression tests. It is not a review of an immutable commit.

## Findings fixed

| Finding | Resulting behavior |
| --- | --- |
| Parent detail updates were rejected or lost in realtime processing. | Changing, clearing, or moving a child advances the affected parents' timestamps under the project lock. The client preserves explicit `subtasks` snapshots, including an empty array; flat updates preserve the cached expansion. A regression exercises actual client caches with same-user events. |
| Label replacement reported success after a concurrent ticket move prevented the write. | `set_ticket_labels` checks the service result and returns a retryable conflict instead of publishing a misleading success event. A gated concurrent-move regression verifies the destination labels survive. |
| Moving a project to another team left incompatible cycles attached, causing subsequent ticket edits to fail validation. | Project team reassignment locks the project and clears incompatible ticket cycles in the same transaction. Destination-team cycles and tickets in other projects are preserved. Tests cover destinations with and without cycles, followed by a ticket edit. |
| Browser WebMCP registration could reject asynchronously after the hook considered it complete. | Registration exposes a completion promise and an immediately available disposal function. Failures clean up prior registrations and reach the hook's error handler; disposal can cancel pending registration. |
| The standalone server lockfile did not include the new server dependencies. | `server/package-lock.json` is synchronized for the server-only install used by the container build. Final container-build verification is tracked below. |
| Legacy HMAC secrets containing `:` or `=` could be mistaken solely for keyed-secret entries. | Rotation verification retains the complete configured value as a legacy candidate, including padded secrets, while explicitly keyed tokens still require the matching key entry. |
| Standalone stdio shutdown could leave database or Redis connections open. | EOF and signal shutdown release the event bridge, shared Redis client, and database pool, and remove signal listeners. |
| Redis mutation forwarding used a channel shared across logical databases and deployments. | The channel includes the Redis database number and optional `MCP_EVENT_NAMESPACE`, preventing unrelated configured namespaces from sharing mutation messages. HTTP and stdio processes belonging to one deployment must use matching configuration. |
| An existing branch-slug test failed because underscores were removed before separator normalization. | Client and server branch-name utilities now turn underscores into separators consistently; this small baseline fix is included in the working tree. |
| A restored legacy database still required `cycles.project_id`, blocking creation of modern team-owned cycles. | Bootstrap relaxes the obsolete constraint after backfilling team ownership, preserving existing cycle records and project references. A legacy-schema regression verifies repeated migration and modern cycle insertion; current schemas remain unchanged. |
| Revoking ten old credentials exhausted the shared issuance quota and blocked Generate Connection. | Revocation and creation/refresh have separate named counters while retaining their existing caps. Both limiter implementations return retry delays, and the dialog displays them without discarding an existing configuration. Route regressions cover generation after ten revocations and revocation after issuance throttling. |

## Account settings and OAuth follow-up

Connection management moved from the workspace sidebar to **Account Preferences → Connect External AI**. The account inventory reads only the current user's credentials and current workspace memberships, groups by workspace, and exposes permissions, expiry, client labels, and revocation. New connections offer copyable fields/JSON for custom-header clients and a separate ChatGPT OAuth setup view. A failed inventory refresh cannot close the generated credential view.

OAuth uses the official MCP SDK with a persistent Gravity provider: public-client dynamic registration, authorization-code PKCE S256, explicit browser-session consent, workspace resource binding, one-hour access tokens, and rotating refresh tokens bounded by a 30-day grant. Existing role, workspace policy, and execution checks remain in force. Consent defaults to read tools and supports explicit bulk selection and denial.

Review corrections include:

- Initial unauthenticated OAuth requests reach a 401 discovery challenge under production CSRF protection. The exemption applies only to the OAuth transport, which never authorizes browser cookies; legacy MCP and consent retain CSRF checks.
- Manual refresh cannot convert an OAuth grant into a custom-header credential or change its lifetime. Manual creation cannot claim the reserved OAuth connection type.
- Grant and refresh transactions use their existing database connection for membership/policy reads, avoiding pool-exhaustion deadlocks.
- Unsupported HTTP issuer origins disable OAuth with a clear explanation instead of crashing the application. Manual connections still work. The local `localhost:9999` deployment remains supported.
- OAuth metadata/auth endpoints are proxied by nginx and Vite, and OAuth tool descriptors advertise exact security scopes.

Actual ChatGPT verification is deferred at the user's request because this deployment has no public HTTPS endpoint. Local SDK OAuth verification covers the protocol path; it does not establish a connection from ChatGPT's cloud service.
